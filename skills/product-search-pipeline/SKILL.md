# 商品搜索执行链路

本技能负责**场景识别、槽位提取、关键词与价格参数构造及搜索召回**，为导购推荐与端侧选品提供标准化的输入输出管线。

---

## 1. 交互前置槽位提取

在执行商品搜索前，若本轮尚未确认用户需求槽位，优先提取并整理已识别的槽位信息，建立结构化检索前提：

- **核心槽位清单**：品类、预算、品牌、型号、使用场景、适用人群、面积、尺寸、颜色、材质、核心功能、约束、地区。
- **输出原则**：
  - 仅提炼用户明确表达或可高可靠性归纳的槽位，不确定的槽位不强加假设。
  - 槽位提取后直接进入场景路由与搜索链路，不要停留在纯信息复述。
  - 搜索参数构造时，只传入过滤参数（`keyword` / `priceStart` / `priceEnd` / `sort` / `loc`），不要把场景描述词强行拼入搜索词。

---

## 2. 场景路由

根据用户意图选择对应的检索与交互链路，严禁越界或冗余调用：

| 场景类型 | 触发特征 | 执行流程与核心动作 |
| :--- | :--- | :--- |
| **1. 直接搜索** | 用户明确指定关键词（如"搜 翻领棉服 男"、"找 0.5mm 晨光铅笔"） | `search_products` 直接召回 $\rightarrow$ 简要呈现精选结果卡片。无需复杂的品类框架。 |
| **2. 场景入坑 / 装备清单** | "入坑 XX"、"新手露营装备"、"XX 需要买什么"、"推荐入手 XX" | 建立品类框架 $\rightarrow$ 按品类逐一调用 `search_products` $\rightarrow$ 联动 `shopping-recommendation` 三层推荐（必备/建议/不用买）。缺省槽位先按新手经验默认推进，文末附澄清选项。 |
| **3. 多品类搭配 / 组合** | "通勤西装搭配"、"骑行全套装备"、"帮我配一套 XX" | 梳理主辅品类 $\rightarrow$ 逐一调用 `search_products` 召回 $\rightarrow$ 风格与预算综合平衡推荐。 |
| **4. 预算约束追问** | "500 块搞定"、"预算 1000 帮我选"、"预算多一点 / 少一点" | **复用上轮已识别的品类**（不重新拆分品类），直接按新预算重新计算价格区间并调用 `search_products`。 |
| **5. 普通推荐 / 导购** | "推荐一台笔记本"、"2000 元手机"、"送女友礼物" | `search_products` 召回 $\rightarrow$ 单品精选推荐。需求模糊时先推一批默认推荐，文末再澄清细化。 |
| **6. 商品对比** | "A vs B"、"两款哪个好"、"对比一下区别" | **直接对比不澄清**。提取双方型号/ID，分别检索后输出多维对比表格（核心参数、价格区间、适用人群、优缺点）。 |
| **7. 单品深度追问** | 用户对已推荐商品追问（"这个保修多久？"、"有黑色吗？"） | **不触发新搜索**。基于已有商品信息或进入详情页解答。 |

> **全局规则（先推荐后澄清）**：
> 任何导购场景首轮均禁止"只追问澄清、不给任何推荐"。需求模糊时，先按大众主流默认假设检索并展示初步精选卡片，并在文末提供可点选的细化澄清方向。

## 3. 搜索参数构造规则

### 3.1 关键词（Keyword）构造

1. **词数控制**：总词数（以 `+` 分词）**不超过 4 个**。
2. **去重与精简**：语义重叠词只保留最短或最高频的一个（如"滤茶" + "茶漏" $\rightarrow$ 保留"茶漏"）。
3. **属性词原则**：
   - 关键词仅包含**商品核心属性词**（品类名、品牌、型号、材质、核心功能）。
   - 场景意图与修饰词（如"配裙子"、"送男友"、"办公室用"、"平价好用"）**不拼入 keyword**，改用价格与属性筛选控制。
4. **品牌与型号**：用户指定了品牌或具体型号时，原样保留在 keyword 中。

**口语化转换对照表**：

| 用户原始表述 | 提炼 keyword | 价格 / 过滤参数处理 |
| :--- | :--- | :--- |
| "适合打篮球的耐磨鞋子" | `篮球鞋+耐磨` | — |
| "透气的夏天上班穿的西裤男" | `夏季+西裤+透气+男` | — |
| "不贵的送女友生日礼物" | `女友生日礼物` | 设置 `priceEnd` 预算上限 |
| "平价好用的大容量洗面奶" | `洗面奶+大容量` | 设置 `priceEnd` 预算上限，不放"平价好用" |
| "ThinkPad X1 Carbon 2024" | `ThinkPad+X1+Carbon` | 保留完整品牌与型号 |

### 3.2 排序参数（Sort）映射

| 用户表述 | `sort` 参数值 |
| :--- | :--- |
| 综合排序 / 默认 / 你推荐的 | `default` |
| 销量最高 / 买的人最多 / 爆款 / 最热销 | `sales_desc` |
| 价格从低到高 / 便宜优先 / 性价比高 | `price_asc` |
| 价格从高到低 / 旗舰 / 高端奢华 | `price_desc` |

### 3.3 预算转价格区间公式

价格严禁拼入 `keyword`，必须计算并映射到 `priceStart` / `priceEnd`：

| 用户预算表述 | 最低价 `priceStart` | 最高价 `priceEnd` | 逻辑考量 |
| :--- | :--- | :--- | :--- |
| **"预算 X 元" / "X 元左右"** | $X \times 0.6$ | $X \times 1.2$ | 覆盖下探性价比与合理上浮空间 |
| **"X 元以内" / "不超过 X 元"** | $X \times 0.3$ | $X$ | 排除过低劣质品，锁定预算上限 |
| **"平价" / "经济实惠"** | 不设 | 视品类经验设定上限 | 过滤高溢价品牌 |
| **"高端" / "旗舰"** | $X \times 0.7$（若有参考） | 不设 | 锁定核心品质区间 |

### 3.4 多品类预算分配方案

当用户给出总预算（如"3000 元配一套露营装备"）时：
1. **预算充足度评估**：若总预算明显不足以覆盖全部品类，优先建议选购核心高频品类，切忌各品类严重降级摊薄。
2. **分配权重**：
   - **核心品类（必买 ⭐⭐⭐）**：占总预算的 **40% ~ 60%**。
   - **次要品类（建议 ⭐⭐）**：占总预算的 **30% ~ 40%**。
   - **辅助品类（可选 ⭐）**：占剩余预算或建议后置购买。
3. 构造各品类搜索时，`priceStart` 与 `priceEnd` 必须严格基于分配后的区间计算（允许浮动 $\pm 10\%\sim 15\%$）。

## 4. MCP 工具调用规范

在 MCP 环境中，搜索链路优先通过 Native MCP 接口执行：

```javascript
// Native MCP 搜索调用示例
search_products({
  keyword: "露营帐篷+防暴雨",
  sort: "sales_desc",
  priceStart: "300",
  priceEnd: "600"
})
```

- **Fallback 机制**：若 direct search API 不可用或返回空集合，通过 `navigate_to_url` 访问 `https://s.taobao.com/search?q=...`，结合 `scan_page_elements` 扫描候选结果。
- **交易与加购自由度**：召回候选后，支持直接调用 `add_to_cart`、`open_page_panel` 或进入详情页比对真实 SKU 价格。
