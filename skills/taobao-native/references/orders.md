# 订单与包裹追踪

以下流程于 2026-09-27 在淘宝桌面版实测可用。每次调用淘宝原生工具时都要传入 `sourceApp`。

## 收集目标订单

- 使用 `navigate({ page: "order", sourceApp })` 打开订单页，并读取页面内容。
- 按用户给出的日期范围筛选订单，记录订单日期、订单号、商品和当前状态；“从某日开始”包含该日期。
- 若内容被截断，使用 `read_page_content` 的 `offset` 继续读取；若还有分页，检查并逐页收集，确认覆盖完整日期范围后再汇报。
- 保留尚未发货的订单；若订单尚无物流按钮或运单号，标记为“暂未生成运单号”。

## 逐单获取物流信息

对每笔已有物流信息的订单，串行执行以下步骤；不要并行操作多笔订单：

1. 使用 `navigate({ page: "order", searchKey: orderId, sourceApp })` 按完整订单号筛选。
2. 用 `read_page_content` 确认筛选结果中包含目标订单号，再继续操作。
3. 使用 `scan_page_elements({ filter: "查看物流", sourceApp })` 查找物流按钮；根据本次扫描结果取得精确 `index`。
4. 使用 `click_element({ index, sourceApp })` 点击该按钮。每次点击前都重新扫描，不复用旧 `index`。
5. 再次读取页面，确认已进入物流详情，且 URL 中的 `orderId` 与目标订单号完全一致。
6. 从物流详情读取快递公司、`复制` 旁边的运单号及当前物流状态。若页面显示多个包裹，分别记录每个包裹的承运方和运单号。

通过订单页的“查看物流”进入详情页；不要自行拼接未实际观察到的物流 URL。实测详情页路径包含 `/app/dinamic/pc-trade-logistics/home.html`。

## 结果与异常处理

- 根据用户需求汇报订单日期、订单号、商品、快递公司、运单号和物流状态。
- 将运单号按原文作为字符串记录，保留字母前缀和前导零。
- 区分“送达集运仓”和“送达最终收件地址”，不要把集运仓签收误报为最终签收。
- `click_element` 返回 `success: true` 不代表页面已跳转；必须核对详情页 URL 和其中的订单号。
- 若点击后页面未变化，先重新读取当前页并检查加载、弹窗或 Windows 是否锁定；不要反复点击同一按钮。Windows 锁定时停止操作，请用户解锁后再继续。
- 若发现 `安全验证`、`拖动滑块完成验证`、`RGV587_ERROR` 或 `验证码`，立即停止后续订单查询，遵循 `SKILL.md` 中的人机协同流程，等待用户确认后再继续。
- 仅记录流程，不把用户的订单号、运单号、地址或其他订单个人信息写入技能文档。
